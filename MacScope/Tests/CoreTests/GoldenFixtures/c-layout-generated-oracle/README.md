## Identity, comparison and baseline guards

Every baseline ID is the full SHA-256 of its canonical complete input source. Repeated local record names such as `R` are intentional: each case is imported separately. Selection is deterministic by seeded hash, covers every family/part/outcome stratum and every individual feature value, and retains at least one original corpus ID for each minimized root group. Every directed review record is mandatory. Five additional coverage gates require an original nil-inventory example of `_Float16`, `__fp16`, and zero-length arrays of scalars, pointers, and function pointers. These forms are rederived from retained AST models, and their selected cases must be exact or diagnosed refusals. `selection-manifest.json` records complete coverage, minimized witnesses, source triggers, and selected IDs.

`baseline-pass.txt` pins 1114 observed passing IDs. `baseline-refused.json` separately pins 147 exact refusal-reason strings. There are 0 selected `layout-engine-nil-without-parser-diagnostic` cases: they return no total numeric layout and are explicitly recorded as layout-engine abstentions. They are **not** claimed to meet the prompt's parser diagnostic-and-drop refusal wording. Every concrete reported prefix is still checked against Clang, and re-import must preserve the computed result.

The generated tests compare exact sizes/alignments, ordinary offsets, ordered absolute bit offsets/widths including unnamed and zero-width fields, and round trips. ABI checks compare concrete source type metrics even when binding refuses, register spellings, piece ranges, stack transport sizes/alignments and indirect pointee shape. Source object `size`/`align` is separate from compiler-lowered `stack_size`/`stack_alignment`: packing and coercion can make these differ. Where present, `abi_value_size` records the meaningful bytes returned in compiler value lanes, independently of padding in the source object's size. All per-case `type_info` fields are preserved, including this additional compiler metadata.

An old passing ID cannot become a refusal or disappear, including in record mode. An established refusal reason cannot change silently; a verified refusal-to-PASS improvement is allowed. Any remaining wrong result, harness error, ambiguous compiler witness, missing family/root, incomplete full run, changed source digest or inconsistent count blocks fixture publication. Existing baseline expectations are not rewritten to manufacture a pass.
